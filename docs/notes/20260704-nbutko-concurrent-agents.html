Unfamiliar files may be another agent's work in progress

More than one agent session can be working in this repo at the same time — a file you didn't create and don't recognize might be legitimate, not a stray artifact to delete.

author: nbutko · opened: 2026-07-04
When to read this. You (an agent) notice a file in the working tree that you don't remember creating, that isn't mentioned in your own session's plan, and that looks unfinished or unwired — before deleting it, cleaning it up, or silently committing it as your own, read this.

Relevant when

An unexplained file shows up mid-session that you didn't create and can't account for from the task in front of you.

The gotcha

docs/monster-manual.json (a ~4500-line D&D-style monster reference dataset) appeared unexplained mid-session during M0, created by a different concurrent agent session working on future content/roster work — not a bug, not a stray file, and not something the session that found it had asked for. The parallel-worktree structure this project's docs-refactor itself uses (multiple story branches at once) makes this more likely, not less: another session's checked-out worktree or in-flight commit can leave files that look orphaned to a session that hasn't seen the plan behind them.

What to do

Don't assume an unfamiliar file is a stray artifact and delete it, and don't silently commit it as part of unrelated work either — check with the user (or, in a multi-agent/worktree setup, check whether another story/session owns it) before doing either. If it turns out to be legitimate, treat it as that other session's deliverable and leave it for that session (or its commit) to land normally.
