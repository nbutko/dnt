The PWA is hand-rolled, not vite-plugin-pwa

No workbox, no build-time precache list — public/sw.js is a small, dependency-free service worker written by hand, deliberately, so it can't break under rolldown-vite.

author: nbutko · opened: 2026-07-08 · relates to: M4 ship-it plan
When to read this. You're touching offline/installable behavior, wondering why there's no vite-plugin-pwa dependency, or debugging a stale asset served after a deploy.

Relevant when

You're changing caching behavior, adding a PWA feature, or investigating why an old build's assets are still being served after a new deploy.

The gotcha

public/sw.js (confirmed current, 69 lines) is written by hand rather than generated by vite-plugin-pwa/workbox. The project's vite dependency is ^8.1.1, which the file's own header comment calls out as "rolldown-vite" — Vite's Rust-based bundler line — and the comment says a hand-rolled, dependency-free worker "can't break under rolldown-vite" the way a workbox-generated one might. Because there's no build step producing a fixed list of hashed asset names, the worker caches on demand instead of precaching: the first online visit populates the cache, and every later load — including fully offline — is served from it. Navigations are network-first (so a fresh deploy's index.html, and its new hashed asset names, are picked up when online, falling back to cache offline); everything else (hashed JS/CSS, the favicon, Google Fonts) is cache-first. Fonts still load from the Google Fonts CDN at runtime — the service worker caches them after first use, so offline works after one online visit, but they aren't self-hosted. sw.js is excluded from ESLint's typed app graph (.eslintrc.cjs's ignorePatterns) since it uses browser service-worker globals outside any tsconfig.

What to do

Don't reach for vite-plugin-pwa or workbox to "properly" manage the service worker — that was a deliberate choice, not an oversight. If the caching strategy needs to change, edit public/sw.js directly and bump its CACHE constant (currently 'dnt-v1') so the activate handler's cleanup evicts the old cache. If Google Fonts self-hosting is ever wanted (e.g. to make the very first offline visit work before any online visit), that's a real feature, not a bug fix.
