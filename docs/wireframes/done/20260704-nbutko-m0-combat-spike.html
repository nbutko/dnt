Wireframes: M0 Combat Spike

The battle-screen handoff: which direction shipped, which were rejected, and how faithful the mocks were.

feature: m0-combat-spike · author: nbutko · opened: 2026-07-04 · status: done · PRD: no (none was written for M0) · wireframes: yes (this page)

Shipped 2026-07-04, styled in M1's "one real UI" slice. Direction 2a below is what shipped; 2b and 2c were explored and dropped. The as-shipped visual reference now lives in screens.html#battle and visual-spec.html; this page is the original handoff, kept for the record of what was chosen and why.

This wireframe handoff served the M0 implementation plan (no PRD was written for M0 — the roadmap's M0 entry and game-design.html's formulas were the recorded "why").

About the design files

The bundled HTML in the design canvas is a design reference built as an exploratory wireframe/mock deck, not production code — several screens show 2–3 alternative layouts side by side for comparison. It was never meant to be copied directly into the app; the task was to recreate the chosen screens in the target codebase's actual stack (Vite + React + TypeScript + Tailwind, per the architecture doc) using its own patterns — component structure, state management, build tooling — not to embed this HTML as-is.

Fidelity

Mixed, closer to low-fidelity-plus: colors, typography, and component layout were final/intentional and safe to implement as specified. Copy text (monster names, numbers) was placeholder/example data, not final content.

Screen: Battle screen

Which option shipped: direction 2a ("Vertical Duel") — a single centered panel, vertical stack of monster panel → divider → player panel. Options 2b and 2c were alternate layouts explored in the same canvas turn and not chosen; no rationale beyond "2a is the direction" was recorded at the time.

The full visual spec for 2a — outer frame, panel styling, HP bars, the prompt/input row, the countdown column, and the keyboard's three color states — is written up in screens.html#battle (as shipped) and visual-spec.html (the implementer-ready token spec). Restating it a third time here would just drift out of sync with what actually shipped, so this page points at those instead of duplicating the numbers.

See the canvas for 2a alongside the rejected 2b/2c mocks, side by side as originally presented: 2a, 2b, 2c.

Rejected directions

2b and 2c were alternate battle-screen layouts in the same design canvas turn. The handoff recorded only which option was canonical (2a), not the reasoning for rejecting the other two — that reasoning was never written down, so it isn't restated here as if it were.
