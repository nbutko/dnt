ESLint is deliberately pinned to 8.57.1

Not the latest ESLint — eslint-config-airbnb and airbnb-typescript don't support ESLint's flat config, so a newer major would need a compat shim this project doesn't want.

author: nbutko · opened: 2026-07-04
When to read this. You're about to run npm update/npm outdated and see ESLint flagged as behind, or you're tempted to bump it to pick up a new rule or fix a warning about "flat config is the new default."

Relevant when

You're updating dependencies and ESLint (or one of the eslint-config-airbnb* packages) shows up as outdated.

The gotcha

package.json pins eslint to exactly 8.57.1 (confirmed current as of this note), not a caret range. eslint-config-airbnb (19.0.4) and eslint-config-airbnb-typescript (18.0.0) — the base of .eslintrc.cjs — only support ESLint's legacy (.eslintrc) config format, not the flat-config format ESLint 9+ defaults to. Bumping ESLint past 8 would need a FlatCompat shim (or waiting on upstream airbnb-config flat support) that isn't worth the complexity for a solo project.

What to do

Don't bump eslint alone. If ESLint 9+ is ever wanted, that's a deliberate migration: either wait for eslint-config-airbnb/airbnb-typescript to ship flat-config support, or migrate .eslintrc.cjs to a flat eslint.config.js with a FlatCompat bridge and re-verify every rule still applies (the two custom syntax bans — no function, no class — are hand-written no-restricted-syntax rules and should survive either way).
