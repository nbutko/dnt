Wireframes: M2 Progression Loop

The world-map, dungeon-graph, and (retired) Inn-skill-tree handoff: which directions shipped, and the one that didn't survive M3.

feature: m2-progression-loop · author: nbutko · opened: 2026-07-04 · status: done · PRD: yes — M2 PRD · wireframes: yes (this page)

Shipped 2026-07-04. World map (3a) and dungeon graph (3b) below are what shipped and are still current. The Inn skill tree (4a) shipped in M2 and was retired in M3, replaced by ability scores and 5e-style leveling — see its own section below for the record. The as-shipped visual reference for the two surviving screens now lives in screens.html#map and screens.html#dungeon-graph.

This wireframe handoff served the M2 scope doc and the M2 implementation plan.

About the design files

Copied from the M0 wireframe page: the bundled HTML in the design canvas is a design reference built as an exploratory wireframe/mock deck, not production code — several screens show alternative layouts side by side for comparison, and the task was to recreate the chosen screens in the target codebase's own stack, not to embed the HTML as-is.

Fidelity

Copied from the M0 wireframe page: mixed, closer to low-fidelity-plus — colors, typography, and component layout were final/intentional; exact pixel positions in the dungeon-graph SVG (3b) were illustrative for one example run, not a layout algorithm (the real graph is procedurally generated); copy text (monster names, numbers) was placeholder/example data.

Node-state legend

Copied from screens.html#node-states so this page stands alone: the world map's tier cards and the dungeon graph's nodes below both reuse one visual language, unchanged — cleared is a gold radial fill + gold border + glow; available is a dark background + gold border + glow, no fill; locked is dim, with a dashed border and opacity:.55. No screen gets its own separate color language for this.

Screen: The Inn — skill tree (retired)

Retired in M3. The skill tree described below shipped in M2 and was replaced outright by ability scores and 5e-style leveling — see the M3 PRD. XP is no longer a spendable currency. Kept here for the historical record; the palette/type/shape language it established still applies to the M3 screens that replaced it (see screens.html#inn).

Which option shipped: option 4a — no alternatives were explored for this screen in the canvas.

Purpose: spend accumulated XP on five skill-tree branches; each branch was a strictly sequential chain (buy node n before node n+1 unlocks).

Layout: a header bar (back-to-map link, "The Inn — Skill Tree" Cinzel title, XP + coin pill readouts on the right) above five equal branch columns (190px wide, 2px solid #7a5a22 border, 8px radius, background rgba(59,18,32,.25)), laid out with flex-direction:column-reverse inside each so the cheapest node sat at the bottom and the tree visually "grew" upward.

  • Branch order/node counts: Endurance (4 nodes: +20 HP, +20 HP, +1 heart, +1 heart), Wordsmith (5 nodes: unlock text tiers 2/4/6/8/10), Focus (3 nodes, illustrative: +10%/+20%/+35% time limit), Luck (3 nodes, illustrative: +3%/+3% crit chance, +25% crit damage), Utility (3 nodes: +1 power-up slot each). Focus/Luck/Utility node counts and exact percentages were illustrative — never spec'd numerically before the tree was retired.
  • Node states, the same 3-tier language as the other screens: purchased (gold radial fill, gold border, "✓"), buyable now (dark bg, gold border + glow, showing its XP cost as the node's label, tappable), locked (dim, dashed border, opacity:.55, showing "?" instead of a cost). Only ever one buyable node per branch at a time.
  • Vertical connector between nodes: 2px wide, #c9a227 solid if both nodes it joins were purchased (or the lower purchased and upper buyable), #5a4a30 if leading into a locked node.

Interaction (as it worked in M2): tapping a "buyable" node spent XP and immediately flipped it to "purchased," which revealed the next node in that branch as "buyable" (if affordable) or left it locked-but-visible otherwise — cost was always shown even when unaffordable, just not tappable.

See the canvas for the original mock.
