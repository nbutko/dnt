How to read this

Every story below traces back to a specific audit item (the B# bugs from the audit's Part IV ledger, or its Part V recommendation numbers). Same working rules as every other implementation plan: one story = one commit, check-in between, never batch stories; npm run presubmit clean before any code commit; engine/data changes proven headlessly (tests + engine/sim/) before the UI that consumes them; UI verified visually against docs/visual-spec.html and docs/screens.html, not just by tests. Stories are ordered so each phase leaves the game strictly better and shippable — stop anywhere.

Phase A — Live bug fixes (ledger B1–B15)

Story 1 — The typing surface never goes dead B2 + B3 · reported

Focus loss is the "keys stop working" bug; the unclamped dt is its cousin (a backgrounded tab returns to a pair of instantly-expired clocks, which also reads as "the game broke").

  • ui/battle/PlayerPrompt.tsx: wrap the prompt area's container with onMouseDown={(e) => { e.preventDefault(); inputRef.current?.focus() }} — any click inside the battle panel re-arms typing instead of stealing focus. Add an onBlur on the hidden input that refocuses (via requestAnimationFrame, so the loss-screen Continue and modals can still take focus when the fight is over/paused: only refocus while !disabled && !paused).
  • Give the whole battle screen the same courtesy: a click on the monster panel or the on-screen keyboard (the biggest accidental click target) must also route focus back — one handler on the Frame, not one per panel.
  • ui/hooks/useGameLoop.ts: clamp the computed frame delta — const dt = Math.min(time - last, MAX_FRAME_DT_MS) with MAX_FRAME_DT_MS = 250. A backgrounded tab then resumes having "lost" at most a quarter-second of clock instead of the whole absence. (The battle deliberately does not simulate while hidden — hearts/HP must not drain unattended.)
  • Tests: jsdom — blur the input mid-battle, assert focus returns; unit — a 60,000ms frame ticks the engine 250ms.

Done when: mid-fight, click every visible element then type — input lands; switch tabs 10s and return — both countdowns resume where they left off. Verify on the real Chromebook.

Story 2 — Wrapped lines never start with a space B1 · reported

  • ui/battle/TypedProgress.tsx (wrapPrompt): when a whitespace token doesn't fit the current line, append it to the just-flushed line's tail instead of seeding the next line with it — the trailing space is invisible (each line renders whiteSpace: 'pre' inside an overflow-hidden box), and the 1:1 char↔glyph index map is untouched. Word tokens keep the existing flush-then-place behavior.
  • Check the caret-at-boundary rule still reads right: after the player types the (now line-tail) space, the caret should appear at the start of the next line, before its first visible letter — adjust the "caret belongs to the later line" test to the new split.
  • Unit tests on wrapPrompt: no line but the first may begin with whitespace, for a corpus sample across tiers 5–14 and a range of cols; total concatenation is always exactly the prompt.

Done when: a tier-12 passage at a narrow window shows every wrapped line flush-left, and typing straight through a wrap never paints a phantom error. Visual check against docs/visual-spec.html's prompt styling.

Story 3 — A chest is not a fight B8 + B10

  • state/dungeon-run/dungeon-run-reducer.ts: track attemptsByNode: Record<nodeId, number>, incremented by resolveFight('lose', …) (ephemeral run state — dies with the run, like everything else there).

Story 6 — Time budgets stop buying damage B13

WIS, Potion of Speed, and the Greataxe tax should move the clock, never the hit — every doc frames them as tempo levers, and speedBonus currently leaks them into offense.

  • engine/battle.ts: keep two numbers per prompt — expireLimitMs (base + timeBudgetBonusMs, drives the countdown and expiry, unchanged) and scoringLimitMs (the un-bonused base), passed as computeDamage's timeLimitMs. speedBonus then measures the same typing against the same yardstick for everyone. Clamp usedFraction at 1 already handles the "used more than the scoring limit" case (a slow-but-in-budget WIS build just gets 1×, never a penalty).
  • engine/sim/: re-run the retune sweep; expected shift is small (speedBonus was near its 2× cap for fast typists anyway) but the behind corner must stay at its Story-2-retune win rates — that corner leans on WIS. If it regresses, compensate in wisTimeBudgetMsPerMod (a values edit), not by reverting the decoupling.
  • Tests: same input trace with and without timeBudgetBonusMs deals identical damage; Greataxe's tax shortens the clock but not the hit.

Done when: sweep results are within tolerance of the committed baseline everywhere except the intended stat semantics.

Story 10 — Rolling high always hits harder audit finding 3 (band inversion)

  • config/combat.ts (or a sibling config/text-tiers.ts): an authored, monotonically increasing damageFactorByTier: number[14] — seeded from today's measured per-tier average lengthFactors, then hand-raised at the inverted rungs (tiers 4 and 6) so the ladder strictly climbs.
  • engine/damage.ts: lengthFactor(charCount, servedTier, combat) becomes tier-anchored — the tier factor is the center, and raw char count only wobbles ±10% around it within the tier (so a long tier-7 line still beats a short one, but no tier ever undercuts the tier below). battle-store.ts already knows the served tier; thread it through BattleConfig.
  • Invariant test: for every dungeon's [low, mid, high] band, expected damage factor is non-decreasing in the roll — the test that would have caught this.

Done when: in D2, a high-band fight out-damages a mid-band fight out-damages a fumble, measurably, and the sweep's corner win rates hold.

Story 19 — Spells & saving throws audit finding 8 · fixes the Wizard

The biggest story here — treat its first task as a mini-scope to review before building.

  • Scope note first (half a page in this doc or its own file): the spell list (3–4 to start — Magic Missile: auto-damage; Shield: negate the next monster hit; Fireball: next hit rolls extra dice; Guidance-as-cantrip is already an item), slots-per-dungeon by level, and the exact typed-incantation flow: pick the spell in the encounter modal (window ②, no mid-typing input), its verbal component is prepended to the fight's first prompt; type the whole line clean → the spell fires with the hit. A miss fizzles the slot — dramatic, fair, very D&D.
  • Wizard gets slots natively (this is the class fix — Story 12's parity table is the before/after evidence); other classes can find single-use scrolls in chests (consumable machinery reused).
  • Saving throws: each boss (bosses only, to start) gets one signature move keyed to an existing stat window — when it fires (first time boss HP crosses 50%, say), an auto-rolled CON or DEX save shows in a flash + brief banner (advantage/items apply); success halves the effect (Medusa: lose 3s of time budget this prompt; Kraken: next player hit −25%). Resolution is window ③ — automatic, a flash, never input.
  • Engine first, headless: slot accounting, incantation-prefix prompt source, save-roll resolution — all pure; UI after.

Done when: the Wizard's parity delta (Story 12 baseline) closes to the pack, and the kid can explain what a saving throw is because he's watched himself make one.
