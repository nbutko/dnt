2. How the sorting was done

  • Evergreen = still true about the repo, or fixable to be true by rewriting in the present tense. Test: would a reader in six months be misled by a sentence? If the sentence is a "why" that still holds, it stays; if it is a narrative of how things changed, it goes to done/ and gets linked.
  • PRD-shaped = what the player gets and why: rules, screens described from the player's seat, target numbers, open questions about the experience.
  • Plan-shaped = how: file/component layout, state homes, seams, API sketches, stories with tasks, "done when," out-of-scope lists, review-note tables, post-playtest checklists.
  • Wireframe-shaped = the screens themselves and the option comparisons that picked them.
  • Note-shaped = a gotcha: something surprising that cost time and would cost it again.
  • The old scope/implementation pairs already split cleanly along PRD/plan lines by intent; the mess is in the docs that grew by accretion (content plan ×3, design README, roadmap, index).
  • Feature names below are candidates. The constraint that matters is that a feature's PRD, wireframes, and plan share one name.
