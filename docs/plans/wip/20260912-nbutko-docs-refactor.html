Plan: Docs Refactor

Move, split, and scrub every document in docs/ into the evergreen / artifact / note layout, one source document at a time, with the links clean after every commit.

feature: docs-refactor · author: nbutko · opened: 2026-09-12 · status: wip · PRD: yes · wireframes: no (no screens change)

This is the implementation plan for docs-refactor. The PRD says what the layout must be and why (requirements R1–R12); the inventory note is the raw material — what every current file contains and who links to it. This document makes the calls the note left open, fixes every file's destination, and breaks the work into stories that each end in one link-clean commit.

1. Scope

  • In: everything under docs/; CLAUDE.md; the twelve source files and two content-pipeline/ files whose comments cite a doc path (plus the comments that cite a doc by bare name — found by grep, per §2.2); the maintainer's session memory (project-status files migrate into notes).
  • Out: game code, tests, and the build. The one code touch is the path content-pipeline/manifest-gen.ts reads monster-manual.json from (see §4). No new tooling: the link audit in §7 is a script an agent runs, not CI.
  • Deliverable: the tree in §3, every file in it true or banner'd, the four indexes complete, the conventions doc and templates written, and this PRD + plan closed into done/ as the first worked example.

2. Approach

2.1 Order of operations — what is cheapest for agents

The expensive resource here is agent context, not keystrokes. The documents being reshaped are 20–96 KB each; loading one costs more than any amount of sed. So the plan is organized around one rule:

Read each source document once. In the story that handles it, an agent reads the document, writes every output it produces (PRD, plan, wireframe page, evergreen doc, notes) with their final paths and links, removes the original, repoints every inbound link, updates the indexes, and runs the link audit — then commits. No document is moved in one story and split in another.

That rule, plus the requirement that links resolve at every commit, gives this order:

  1. Scaffold first (Stories 0–1). Create the directories, move the stylesheet into style/ and relink every existing document once, write the conventions doc, templates, and the four index pages. After this, every destination exists and no later story touches a file just to fix its <link rel="stylesheet">.
  2. Then the design folder (Story 2). The milestone plans link into the wireframes, so the wireframes must land first. This is also the story that dissolves design/README.md, whose content fans out to three destinations; doing it in one story means the README is read once.
  3. Then one feature per story, chronologically (Stories 3–8). M0, M2, M3, content v1+v2, the combat retune, M5. Each story is independent of the others once Story 2 is in; they only share the index pages, docs/index.html, roadmap.html, and CLAUDE.md, where each story makes one-line href repoints.
  4. Then notes and memory (Story 9). Gotchas from CLAUDE.md and memory become notes; the memory files are pruned. Done after the feature stories so the notes Stories 4 and 7 mine from the M2 tails and the retune are already in place and the rest of the index fills in one pass.
  5. Evergreen scrub last (Story 10). The top-level docs must link to final paths and state the final truth, and checking numbers against src/config/ should happen once. The index page is rewritten wholesale here; until then it carries the old cards with repointed hrefs.
  6. CLAUDE.md rewrite and full audit (Story 11), then close-out (Story 12).

2.2 Working rules for every story

  • git mv for whole-file moves. For a split, git mv the original to its largest output (usually the plan) so history follows the bulk of the text, then create the smaller outputs as new files. git rm only when every section of a file has landed somewhere.
  • Mechanical edits by script, not by hand. Stylesheet relinks, href repoints, and source comment updates are sed/grep jobs. Only the splits and scrubs need a document actually read.
  • Find inbound links by grep, not memory. Before removing an old path, run grep -rl '<old basename>' docs CLAUDE.md src content-pipeline and fix every hit. The audit script in §7 is the backstop.
  • Forward links use today's path. A banner or note written in one story that links a document a later story moves (Story 4's link to the M3 PRD, Story 7's to the M5 PRD) targets that document's current path, so the audit stays clean; the later story's inbound grep repoints it.
  • Interim index rule. Until Story 10, docs/index.html keeps its old cards; a move story only repoints the card's href. A card is never left pointing at a deleted file.
  • The split in §3–§5 is a proposal, not a decree. Whoever reads a source document (usually a subagent handling one story) is the only one who has actually seen it whole, and may come back with a different split — fewer or more outputs, a section that belongs elsewhere, a feature name that fits better — with a sentence of reasoning per change. The orchestrating agent is the arbiter: it accepts or rejects, and on acceptance updates §3, §5, and the story's tasks in the same commit as the content, so this plan always matches the tree. A proposal that would move content out of docs/, delete content, or change a path that code reads goes to the maintainer at the check-in instead.
  • Banners, not rewrites. A relocated done document gets a status banner at the top (what shipped, what didn't, where the evergreen description now lives, "reconstructed" if applicable) and reconciled checkboxes. Its body is restated and reorganized, never re-argued. Verification boxes that were never ticked stay unticked and the banner says so.
  • Over-split, tolerate redundancy. When a section serves two documents, copy it into both (with a one-line "copied from …" note) so each document reads on its own. A reader should never have to open a second file to understand the one in front of them.
  • Every story ends the same way: run the link audit, run the index check, open one moved file at its new depth via the dev server (and, if a human is present, via file://), commit, stop, check in.
  • Source-comment stories run npm run lint (they touch src/, even if only comments). Pure docs commits skip presubmit per CLAUDE.md.

2.3 Parallelism

Stories 3–8 are independent after Story 2 and could run in parallel worktrees, one feature each. The only merge points are the index pages, docs/index.html, roadmap.html, and CLAUDE.md, all of which take one-line additions per story and merge trivially. The default is still one agent in sequence with a check-in per story — the "one story = one commit" rule is the point, and the total is a day's work, not a week's. Parallelize only if a second agent is idle anyway.

7. Verification toolkit

7.1 Link audit (filesystem, not HTTP)

The dev server's SPA fallback returns 200 for anything, so links are checked on disk. Run from the repo root after every story; exit code 0 and no output means clean. (Until Story 2 removes it, the canvas's ./support.js line is the one expected hit — Stories 0 and 1 are clean apart from that.)

python3 - <<'PY'
import re, sys, pathlib, urllib.parse
root = pathlib.Path('.')
bad = []
strip = lambda s: re.sub(r'<(pre|code)>.*?</\1>', '', s, flags=re.S)  # quoted markup isn't a link
# 1. every href/src inside docs/
for f in root.glob('docs/**/*.html'):
    text = strip(f.read_text(errors='ignore'))
    for m in re.finditer(r'(?:href|src)="([^"#]+)(#[^"]*)?"', text):
        target = urllib.parse.unquote(m.group(1))
        if re.match(r'^(https?:|mailto:|data:|javascript:)', target): continue
        p = (f.parent / target).resolve()
        if not p.exists(): bad.append(f'{f}: {target}')
# 2. every docs/... path mentioned outside docs/
for f in [root/'CLAUDE.md', *root.glob('src/**/*.ts'), *root.glob('src/**/*.tsx'),
          *root.glob('src/**/*.css'), *root.glob('content-pipeline/**/*.ts'), root/'vite.config.ts']:
    if not f.exists(): continue
    for m in re.finditer(r'docs/[\w./ -]+?\.(?:html|json|md|css)', f.read_text(errors='ignore')):
        if not (root / m.group(0)).exists(): bad.append(f'{f}: {m.group(0)}')
print('\n'.join(bad)); sys.exit(1 if bad else 0)
PY

Fragments (#t4, #node-states) are not checked by the script; the stories that move anchored documents check theirs by grep (grep -c 'id="t4"').
