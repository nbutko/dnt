Filenames that differ only in case break tsc -b

Two files whose names differ only by capitalization (e.g. keyboard.ts vs. Keyboard.tsx) fail TypeScript's build-mode casing check with TS1149/TS1261 — not just a macOS-filesystem quirk.

author: nbutko · opened: 2026-07-04
When to read this. You're about to name a new file, and an existing file in the same (or a case-insensitively-colliding) directory has a similar name with different capitalization — or npm run build fails with TS1149/TS1261 mentioning two files that look almost identical.

Relevant when

You're adding a new source file and another file's name differs only in capitalization, or a build fails citing TS1149/TS1261.

The gotcha

src/ui/battle/keyboard.ts (the module) collided with src/ui/battle/Keyboard.tsx (the component) during M0 — names identical except for the leading letter's case. tsc -b's cross-file casing check treats this as an error (TS1149/TS1261) on any filesystem, including case-sensitive ones — this is a TypeScript project-reference rule, not a workaround for macOS's (usually case-insensitive) filesystem. The build fails even though the two files coexist fine on disk.

What to do

Pick names that differ by more than case. The module was renamed keyboard.ts → keyboard-highlights.ts (still true today, alongside Keyboard.tsx and keyboard-highlights.test.ts) rather than trying to make the casing work. Before naming a new file, check for an existing file whose name matches yours case-insensitively.
