A flex item's default min-width: auto can blow out to thousands of pixels

Without min-w-0, a flex child holding unbroken text sizes itself to fit that text instead of wrapping — the battle panels once measured a 6581px-wide column before this was found.

author: nbutko · opened: 2026-07-09
When to read this. You're building a flex layout that's supposed to wrap or truncate long text (a prompt panel, a name field, any flex-1 child with a text node inside), and the column is instead stretching far wider than its container.

Relevant when

A flex-1 (or similar) child containing text isn't wrapping/truncating as expected and the layout stretches unexpectedly wide.

The gotcha

A flex item's default min-width is auto, which means "at least as wide as my content" — for a text node with no natural break points (a long unbroken passage, or one Tailwind's default flex-1 doesn't override), that lets the item's measured width blow past its flex container entirely instead of wrapping or shrinking. This surfaced in the M5 multiline-typing work (commit f1f7f4f) as a non-wrapping battle line measuring 6581px wide instead of respecting the panel's intended column width.

What to do

Add Tailwind's min-w-0 to any flex-1 (or other flex-grow) container that's supposed to wrap or truncate its text content. Both battle panels in src/ui/battle/BattleScreen.tsx carry it today (confirmed at the two min-w-0 flex-1 divs, with an inline comment explaining why) — copy that pattern for any new flex column that holds prompt/name/label text rather than rediscovering the bug.

History
