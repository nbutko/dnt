IndexedDB's open() can hang forever with no error

A wedged origin's IndexedDB store never fires success, error, or blocked — code that awaits the open call can wait forever, silently.

author: nbutko · opened: 2026-07-05
When to read this. You're touching anything that opens an IndexedDB database (the save store, or any future one) and gating UI on that open resolving — or you're debugging a screen that renders blank/frozen with no console error, especially right after a browser profile has been doing heavy DevTools/storage work. The symptom looks like a code bug (a stuck promise) but the actual cause is the browser's IndexedDB implementation itself declining to ever answer.

Relevant when

You're writing or reviewing code that awaits an IndexedDB open (or any promise gating first paint) and need to decide whether — and how — to bound that wait.

The gotcha

state/save/save-storage.ts opens the save database via idb's openDB(), and SaveProvider originally gated the entire UI on that promise resolving (if (!hydrated) return null). During M2 playtesting this produced a permanent black screen on one Chrome profile at localhost:5173 — no error in the console, nothing thrown, the underlying IDBOpenDBRequest just sat at readyState: 'pending' forever. It fired none of success, error, or blocked. The same code worked fine seconds later at 127.0.0.1:5173 (see the companion note on origins) — this was a wedged per-origin IndexedDB store, not a code bug, but the code had no way to notice or recover.

What to do

Never await an IndexedDB open (or any storage open) as the sole gate on rendering something. Race it against a timeout and treat "timed out" the same as "rejected": fall back to an in-memory default and let the app come up, rather than trusting the platform to always tell you it failed. state/save/SaveProvider.tsx now does exactly this (LOAD_TIMEOUT_MS, currently 4000ms) — whichever of the real load or the timeout settles first wins, so a merely-slow load still gets its real data, but a hung/wedged open can no longer blank the screen. If you add a second IndexedDB-backed store later, give it the same race, not just a bare await.
